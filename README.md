# Marico Cafe 来場者サイト

GitHub Pagesで配信する静的サイトです。`index.html`の各ゲーム紹介のタイトル下に、、認証不要の公開API `GET /v1/status` を取得します。

## 接続先

現在は `https://shikosai-api-staging.sg-tera.workers.dev/v1/status` に接続しています。例示ゲームのテスト環境です。本番APIは未作成です。

本番切替時は、`index.html` の `#game` にある `data-api-url` を本番の公開一覧URLに変更し。認証IDは不要です。公開HTMLに認証IDを入れないでください。

ゲーム紹介の `data-game-id` とAPIの `gameId` を対応させ、タイトルの下に「空き／利用中」と利用中の終了予定を表示します。名前・紹介文・人数・公式リンクは静的HTMLで管理します。掲載中の8ゲームには表示順にID 1〜8を割り当てています。本番DBにも同じIDとゲーム名を登録してください。ID未設定・APIに存在しないIDは「未確認」です。

## 更新と失敗時の動作

- 初回、表示中60秒ごと、非表示から復帰した時、手動ボタンで取得します。重複取得を防ぎ、非表示中は定期取得を停止します。
- 10秒でタイムアウトします。失敗直後の自動再試行はしません。
- 失敗時は前回の一覧と最終取得成功時刻を保持します。初回失敗は「未確認」と表示します。
- 終了予定は日本時間の目安として表示します。予定超過で自動的に空きへ変更しません。
- 状態は `textContent` で挿入します。

## 検証

Node.js 20以上で `node --test tests/congestion.test.cjs` を実行できます。追加パッケージは不要です。実際の画面スクリプトを使い、取得成功、初回・途中失敗、不正応答、空配列、タイムアウト、重複防止、非表示・復帰を検証します。

ブラウザではローカルHTTPサーバーで表示し、API接続とスマホ幅でのレイアウトを確認してください。デプロイは既存のGitHub Actionsが `main` へのpush時に実行します。
